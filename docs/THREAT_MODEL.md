# CEAL 威胁模型

## 保护对象

- 用户源码、未提交改动和生产数据；
- 任务授权边界与架构合同；
- 测试、运行日志、截图、产物和 SHA-256；
- Secret、令牌、模型资产与付费额度；
- Git 历史、版本和发布状态。

## 主要威胁

| 威胁 | 默认处置 |
|---|---|
| 越过 allowlist 或命中 denylist | HOLD，提交 Change Request |
| 伪造测试、mock 冒充 runtime、历史 PASS | HOLD/BLOCK，不得关闭 |
| 写入 Secret 或在日志暴露 token | BLOCK |
| 生产数据写入或测试副作用 | BLOCK，保留现场 |
| 未授权付费/外部调用 | BLOCK |
| 破坏性命令或不可逆升级 | BLOCK 并请求明确授权 |
| 创建第二套平行系统 | HOLD，优先复用现有组件 |
| 依赖或 lockfile 漂移 | HOLD，必须进入任务范围 |
| deadline 迫使降级门禁 | 不改变原决定 |
| 重试循环掩盖根因 | HOLD，耗尽预算后诊断 |

## 非目标

CEAL v0.1 不提供：

- 密钥托管；
- 沙箱或操作系统级强制隔离；
- 数字签名服务；
- GitHub 分支保护自动配置；
- 第三方依赖漏洞扫描；
- StudioOS 产品运行时证明。

这些能力只能由对应平台真实配置和单独验收，不能因本仓库存在策略代码而视为完成。
